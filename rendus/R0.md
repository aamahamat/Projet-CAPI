## 1. CU-01 : Estimer le backlog d'un projet

| Rubrique | Contenu |
|---|---| 
| **Portée et niveau** | Application CAPI . utilisateur |
| **Acteur principal | Organisateur |
| **Intervenants et intérêts** | **Membres (Joueurs & Organisateur)** : veulent estimer correctement l'ensemble des tâches du backlog.<br>**Système (CAPI)** : doit appliquer rigoureusement les règles de validation choisies et gérer les sauvegardes JSON. |
| **Declencheur** | L'organisateur souhaite lancer une session d'estimation d'un backlog. |
| **Garanties** | Minimale : Un fichier backlog au format JSON est disponible . De succès : le backlog est entièrement estimé et exporté dans un nouveau fichier JSON.

### Scénario nominal
1. <L'organisateur configure la session>
2. <L'organisateur charge le backlog de taches au format JSON>
3. <Les joueurs estiment chaque fonctionnalité>
4. <Le système applique la règle de validation choisie>
5. <L'application enregistre le fichier JSON final contenant chaque fonctionnalité et sa difficulté>

### Extensions
- **<2>a.** Le backlog chargé est invalide :
  - **<2>a1.** Le système affiche un d'erreur.
  - **<2>a2.** L'organisateur vérife le format choisi et reprend le scénario 2.
- **<3>a.** Tous les joueurs jouent la carte café :
  - **<3>a1.** Le système sauvegarde l'etat d'avancement dans un fichier JSON pour une reprise ulterière.
- **<3>b.** Les joueurs reprennent la partie sauvegardée :
  -- **<3>b1.** L'organisateur recharge le fichier JSON et ils reprennent le scénario 3.

## 2. Les 6 user stories

| US | Texte (En tant que... je veux... afin de...) | Source | MoSCoW |
|---|---|---|---|
| US-01 | En tant que joueur, je veux que mon vote ne soit validé que si toute l'équipe choisit la meme valeur, afin de garantir un choix strict sur chaque fonctionnalité.|5 (fonctionnalités obligatoires) | Must |
| US-02 |En tant qu'organisateur, je veux paramétrer la règle de validation, afin de limiter un vote à l'infini. |5 (fonctionnalités obligatoires) | Must |
| US-03 |En tant que joueur, je veux qu'au premier tour tous les joueurs soient d'accord sur l'estimation de l'effort de la fonctionnalité afin que les votes soient identiques |5 (fonctionnalités obligatoires) | Must |
| US-04 |En tant qu'organisateur, je veux charger le backlog au format JSON, afin de permettre le bon deroulement du jeu. |CU-01 étape 2 | Must |
| US-05 |En tant que joueur, je veux que la session se sauvergarde automatiquement dans un fichier JSON lorsque tous les joueurs jouent la carte café, afin qu'on puisse reprendre le jeu plus tard. |CU-01 extension 3a1 | Should |
| US-06 |En tant que joueur, je veux choisir une carte de vote afin d'estimer la difficulté de la fonctionnalité courante. |CU-02 étape 1 | Must |

Parmi ces 6 US, 3 portent les règles de validation : règle stricte, règle choisie, premier tour à l'unanimité.

## 3. CU-02 : Voter sur une fonctionnalité

| Rubrique | Contenu |
|---|---| 
| **Portée et niveau** | Application CAPI . utilisateur |
| **Acteur principal | Les membres |
 **Intervenants et intérêts** | **Organisateur : veut estimer correctement l'ensemble des tâches du backlog |
| **Declencheur | Le système affiche une nouvelle fonctionnalité |
| **Garantie Minimale : La fonctionnalité courante est affichée . De succès : une valeur d'estimation finale est validée et enregistrée 

## Scénario nominal
1. <Chaque joueur choisit sa carte de vote pour la fonctionnalité courante>
2. <Le système devoile les cartes choisies par les joueurs>
3. <Le système applique la règle de validation>
4. <Le système enregistre l'estimation et passe à la fonctionnalité suivante>

## Extensions 
- **<2>1.** Les joueurs sont en mode local :
  - **<1>a1.** Les joueurs votent chacun à leur tour sur le meme appareil, sans voir les votes des autres avant la révelation.
- **<2>a.** Le vote est different au premier tour :
  - **<2>a1.** Les joueurs (min - max) expliquent leurs choix.
  - **<2>a2.** Les joueurs s'entendent sur une valeur à l'unanimité.
- **<2>b.** Le vote est different au deuxième tour :
  - **<2>b1.** Le système applique la règle choisie (mediane, moyenne, majorité absolue, majorité relative).
