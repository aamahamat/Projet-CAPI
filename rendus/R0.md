## 1. CU-01 : Estimer le backlog d'un projet

| Rubrique | Contenu |
|---|---| 
| **Portée et niveau** | Application CAPI . utilisateur |
| **Acteur principal | L'organisateur |
| **Acteurs secondaires | Les membres et le système |
| **Declencheur | L'organisateur souhaite lancer une session d'estimation d'un backlog |
| **Garantie Minimale : Un fichier backlog au format JSON est disponible . De succès : le backlog est entièrement estimé et exporté dans un nouveau fichier JSON

### Scénario nominal
1. <L'organisateur configure la session>
2. <L'organisateur charge le backlog de taches au format JSON>
3. <Les joueurs estiment chaque fonctionnalité>
4. <Le système applique la règle de validation choisie>
5. <L'application enregistre le fichier JSON final contenant chaque fonctionnalité et sa difficulté>

### Extensions
- **<2>a.** Le backlog chargé est invalide :
  - **<2>a1.** Le système affiche un d'erreur
  - **<2>a2.** L'organisateur vérife le format choisi et reprend le scénario 2
- **<3>a.** Tous les joueurs jouent la carte café :
  - **<3>a1.** Le système sauvegarde l'etat d'avancement dans un fichier JSON pour une reprise ulterière
- **<3>b.** Les joueurs reprennent la partie sauvegardée :
  -- **<3>b1.** L'organisateur recharge le fichier JSON et ils reprennent le scénario 3

## 3. CU-02 : Voter sur une fonctionnalité

| Rubrique | Contenu |
|---|---| 
| **Portée et niveau** | Application CAPI . utilisateur |
| **Acteur principal | Les membres |
| **Acteur secondaire | L'organisateur
| **Declencheur | Le système affiche une nouvelle fonctionnalité |
| **Garantie Minimale : La fonctionnalité courante est affichée . De succès : une valeur d'estimation finale est validée et enregistrée 

## Scénario nominal
1. <Chaque joueur choisit sa carte de vote pour la fonctionnalité courante>
2. <Le système devoile les cartes choisies par les joueurs>
3. <Le système applique la règle de validation>
4. <Le système enregistre l'estimation et passe à la fonctionnalité suivante>

## Extensions 
- **<2>1.** Les joueurs sont en mode local :
  - **<1>a1.** Les joueurs votent chacun à leur tour sur le meme appareil, sans voir les votes des autres avant la révelation
- **<2>a.** Le vote est different au premier tour :
  - **<2>a1.** Les joueurs (min - max) expliquent leurs choix
  - **<2>a2.** Les joueurs s'entendent sur une valeur à l'unanimité
- **<2>b.** Le vote est different au deuxième tour :
  - **<2>b1.** Le système choisit une règle (mediane, moyenne, majorité absolue, majorité relative)
